# 🤖 ИИ-расширение на ГигаЧате

Это расширение базового проекта. Оно работает **поверх** основной системы:
сначала письма читаются и классифицируются базовой логикой
(`email_message.py` + `classifier.py`), и только потом ИИ-модель **ГигаЧат**
обогащает уже разобранные письма дополнительными действиями. Без базовой части
расширение не имеет смысла — оно опирается на её результат (категорию письма).

## ✨ Что умеет

Расширение добавляет три функции:

1. **📝 Поиск задач со сроком** (`extract_tasks`)
   Находит в письме обещания вроде «пришлю отчёт до вторника» и предлагает
   завести задачу, чтобы договорённость не потерялась.

2. **🛡️ Детектор фишинга** (`check_phishing`)
   Оценивает, похоже ли письмо на обман или социальную инженерию: давление,
   срочность, просьбы срочно перевести деньги или сообщить пароль.

3. **✉️ Черновик ответа** (`draft_reply`)
   Генерирует короткий вежливый черновик ответа от IT-поддержки на письмо.

## 🔗 Как связано с базовой частью

Фичи применяются **в зависимости от категории**, которую присвоила базовая
система. Это и есть связь расширения с основной логикой:

| Категория письма (из базы) | Какие ИИ-фичи применяются |
|---|---|
| `important` | черновик ответа + поиск задач + проверка на фишинг |
| `requests` | черновик ответа + поиск задач |
| `spam` | проверка на фишинг |

Пайплайн целиком:

```
inbox/ ─▶ чтение ─▶ классификация ─▶ (базовая часть закончилась)
                                          │
                                          ▼
                              ИИ-фичи по категории письма
                         (черновик ответа / задачи / фишинг)
```

## 📁 Файлы

```
ai_features/
├── gigachat_client.py   обёртка над API ГигаЧата (+ офлайн-режим)
├── features.py          три фичи (по одной функции на каждую)
├── demo.py              демонстрация фич на письмах из inbox
├── .env.example         пример файла с ключом
└── README.md            этот файл
```

- **`gigachat_client.py`** — класс `GigaChatClient` с одним методом `ask()`.
  Он получает временный токен по ключу авторизации и отправляет запрос модели.
  Если ключа нет или нет интернета — автоматически переключается на офлайн-режим
  (простые правила вместо модели), чтобы приложение не падало.
- **`features.py`** — три функции, каждая берёт письмо (объект `EmailMessage`
  из базовой части) и клиента, формирует запрос к модели и возвращает ответ.
- **`demo.py`** — берёт первые письма из `inbox`, классифицирует их базовым
  классификатором и показывает работу фич.

## ⚙️ Как реализовано

ГигаЧат работает по протоколу OAuth: сначала по ключу авторизации запрашивается
временный access-токен (адрес `ngw.devices.sberbank.ru`), затем с этим токеном
отправляется сам запрос к модели (адрес `gigachat.devices.sberbank.ru`). Вся эта
логика спрятана в `GigaChatClient`, поэтому фичи в `features.py` остаются
простыми — они просто вызывают `client.ask(...)`.

Клиент ищет ключ в таком порядке: аргумент конструктора → переменная окружения
`GIGACHAT_API_KEY` → файл `.env` → встроенный ключ по умолчанию. Благодаря этому
проект **работает сразу после клонирования**, но ключ при желании легко заменить
своим, не меняя код.

## 🚀 Как запустить

Расширение запускается из корня проекта (на уровень выше папки `ai_features`):

```bash
python3 -m ai_features.demo
```

Для реального обращения к модели нужна библиотека `requests`:

```bash
pip install requests
python3 -m ai_features.demo
```

Если `requests` не установлен или нет интернета — расширение всё равно
отработает в офлайн-режиме и покажет, как устроены фичи.

### Свой ключ (необязательно)

Чтобы использовать собственный ключ вместо встроенного, создайте файл `.env`
в корне проекта:

```bash
echo 'GIGACHAT_API_KEY=ваш_ключ' > .env
```

Ключ берётся из личного кабинета GigaChat API (scope `GIGACHAT_API_PERS`).

## 🖥️ Что увидите при запуске

Для каждого из первых писем выводится его категория и результат работы фич,
например:

```
==================================================
Письмо: mail_0012.txt | категория: important
Тема: URGENT: BI-система не отвечает

[Черновик ответа]
Здравствуйте! Мы получили ваше обращение о недоступности BI-системы...

[Задачи со сроком]
В письме есть просьба восстановить доступ как можно скорее.

[Проверка на фишинг]
НЕТ. Письмо от внутреннего адреса, признаков обмана нет.
```

## 🧩 Почему так сделано

- Каждая фича — отдельная функция: её легко понять, объяснить и протестировать.
- Клиент ГигаЧата отделён от логики фич: если изменится API, правится один файл.
- Офлайн-режим гарантирует, что расширение можно показать в любой момент —
  даже без интернета или если ключ перестанет работать.
