# 📬 Сортировщикоинатор3000

**Автоматизированная система обработки корпоративной почты IT-поддержки.**

Приложение читает входящие письма из файловой системы, классифицирует их по
смысловым категориям на основе правил, раскладывает по папкам и формирует
журнал работы со статистикой.

---

## 🎯 Задача

Отдел IT-поддержки ежедневно получает сотни писем. Ручная сортировка отнимает
время, а критические инциденты теряются среди рутины и спама. Эта система
автоматизирует разбор входящих: каждое письмо попадает в нужную папку, а на
выходе формируется понятный журнал о проделанной работе.

---

## ✨ Возможности

- 📥 Чтение писем из форматов `.txt` и `.json`, с поддержкой русских
  (`Тема:`, `От кого:`) и английских (`Subject:`, `From:`) заголовков.
- 🧠 Классификация по правилам (ключевые слова) на 5 смысловых категорий.
- 🛡️ **Устойчивость:** письмо без совпадений не теряется, а откладывается на
  ручной разбор; нечитаемые файлы изолируются с записью причины в журнал.
- 📂 Автоматическое создание папок категорий и перемещение писем.
- 📊 Журналирование на базе модуля `logging` (уровни `INFO`/`WARNING`/`ERROR`,
  метки времени) с выводом в консоль и в файл `report.txt`.
- 👀 Режим предпросмотра `--dry-run` — показывает раскладку, ничего не перемещая.

---

## 🗂️ Категории

| Категория       | Что сюда попадает                                            |
|-----------------|-------------------------------------------------------------|
| `important`     | Срочные и критические инциденты, сбои, недоступность сервисов |
| `requests`      | Запросы доступа, проблемы, ошибки, обращения за помощью       |
| `spam`          | Реклама, розыгрыши, «вы выиграли», подозрительные рассылки    |
| `notifications` | Автоматические уведомления, мониторинг, дайджесты             |
| `other`         | Письма без совпадений — **на ручной разбор** (fallback)      |
| `broken`        | Файлы, которые не удалось прочитать (неизвестный формат, повреждённые) |

## 🔄 Как это работает (пайплайн)

```
 inbox/ ──▶ чтение и парсинг ──▶ классификация ──▶ перемещение + журнал + статистика
           (email_message.py)    (classifier.py)         (sorter.py)
                                                              │
                                                              ▼
                              папки категорий/  +  report.txt
```

1. **`email_message.py`** — читает файл письма, распознаёт формат и превращает
   его в объект `EmailMessage` (тема, отправитель, тело). Битые и неизвестные
   форматы порождают исключение `EmailError`.
2. **`classifier.py`** — для каждой категории задан список ключевых слов.
   Письмо относится туда, где совпадений больше. Дополнительно: письма с
   автоматических адресов (`no-reply`, `monitoring`, `alerts@`) распознаются
   как уведомления.
3. **`sorter.py`** — связывает всё вместе: создаёт папки, перемещает письма,
   ведёт журнал (`logging`) и считает статистику.

## 🧩 Устойчивость классификации

Ключевая идея проекта — **ничего не теряется**:

- ❓ **Письмо не подошло ни под одну категорию** → отправляется в `other`
  (ручной разбор). Система не угадывает наугад, а честно откладывает непонятное.
- 🆕 **Появился новый тип обращений** → он тоже попадёт в `other`, а набор
  правил классификатора легко расширяется новыми ключевыми словами без
  переписывания логики.
- 💥 **Файл нечитаемый или неизвестного формата** → изолируется в `broken`,
  причина записывается в журнал. Приложение при этом не падает.

## 🛡️ Обработка проблемных ситуаций

Входные данные намеренно «грязные»: разные форматы, повреждённые и служебные
файлы. Мы заранее продумали проблемные случаи — для каждого есть осознанное
решение:

| Ситуация                                   | Что делает система                  | Почему именно так                                              |
|--------------------------------------------|-------------------------------------|----------------------------------------------------------------|
| Письмо не подходит ни под одну категорию   | → `other`                           | не угадываем наугад; ничего не теряется, всё доступно для разбора |
| Пустое письмо (нет темы и тела)            | → `other`                           | анализировать нечего — безопасный fallback                     |
| Неизвестный формат (`.bin`, `.jpeg`, без расширения) | → `broken`, лог `WARNING`  | принимаем только явные форматы `.txt`/`.json`, остальное — на ручной разбор |
| Повреждённый/нечитаемый файл (не декодируется в UTF-8) | → `broken`, лог `WARNING` | не падаем на бинарных данных, изолируем проблему               |
| Битый JSON                                 | → `broken`, лог `WARNING`           | формат заявлен, но содержимое сломано — на разбор              |
| Скрытые/системные файлы (`.DS_Store`)      | пропускаются                        | служебные файлы ОС — это не письма, не искажают статистику      |
| Подпапки внутри `inbox`                    | пропускаются                        | обрабатываем только файлы                                      |
| Не удалось переместить файл (`OSError`)    | лог `WARNING`, продолжаем           | одно проблемное письмо не должно ронять весь разбор            |
| Папка `inbox` не найдена                   | лог `ERROR`, корректный выход       | понятное сообщение вместо аварийного падения                   |

## 🚀 Запуск

### 1. Клонировать репозиторий
```bash
git clone https://github.com/EgorChulanov/KhakatonBDPM251_Group21.git
cd KhakatonBDPM251_Group21
```

### 2. Запустить через bash-скрипт (рекомендуется)
```bash
chmod +x run.sh        # один раз — выдать право на запуск
./run.sh               # боевой режим: письма перемещаются по папкам
./run.sh --dry-run     # предпросмотр: только показать раскладку
```
Скрипт проверяет наличие папки `inbox`, доступность `python3`, запускает
приложение, выводит итоговый статус и дублирует вывод в `run.log`.

### 3. Или запустить приложение напрямую
```bash
python3 sorter.py             # боевой режим
python3 sorter.py --dry-run   # предпросмотр
```

> ⚠️ В боевом режиме письма **физически перемещаются** из `inbox/` в папки
> категорий. Чтобы сначала посмотреть результат без изменений — используйте
> `--dry-run`.

## 📊 Результат работы

После запуска появляются:

- **Папки категорий** (`important/`, `requests/`, `spam/`, `notifications/`,
  `other/`, `broken/`) с разложенными письмами.
- **`report.txt`** — журнал обработки каждого письма и итоговая статистика
  (с метками времени и уровнями важности):

```
2026-06-01 23:06:11 [INFO] mail_0002.txt -> important
2026-06-01 23:06:11 [WARNING] mail_0104.bin -> broken (не удалось прочитать файл: ...)
...
----------------------------------------
ИТОГ:
  broken: 4
  important: 22
  notifications: 12
  other: 19
  requests: 40
  spam: 12
Всего обработано: 109
```

- **`run.log`** — копия вывода последнего запуска через `run.sh`.

## 🧪 Тестирование

Ключевая логика покрыта тестами на `pytest` (фикстуры, параметризация,
проверка исключений, временные файлы — независимо от содержимого `inbox/`):

```bash
pip install pytest
python3 -m pytest -v
```

Тесты проверяют:
- корректную классификацию по всем категориям;
- граничные случаи: письмо без совпадений, пустое письмо, авто-адрес отправителя;
- чтение `.txt` и `.json` (русские и английские заголовки);
- обработку ошибок: неизвестный формат и повреждённый JSON.
